# 组委会网页编辑器接入

用户当前只有网页编辑权限，主交付采用原生 **GLB 模型 + 大屏 JSON**。不要求修改源码、安装插件或嵌入任意 JavaScript。

## 平台核查依据

2026-11-17 核查并实际接入。公开接口依据来自 `http://121.43.186.114:8085/` 的公开资源 `js/chunk-9cc5af26.8263c278.js`，确认：

- 支持 GLB/GLTF/FBX 模型上传；
- 有“导入/导出 → 导入 JSON”入口，导入会替换当前大屏；文件上限 5 MB；画布基准 1920×1080；
- `screenCenterRack`、`screenCenterInfoCard`、`screenCenterAlarm` 是内置组件；
- 模型组件可调整角度、缩放、位置及整模旋转；没有发现 GLTF 动作播放、动画混合器或内部节点位姿绑定；
- 背景类型只支持 deep/grid/aurora/plain。本配置使用 plain，将模型底图压暗与模糊设为 0，原生卡片保持平台自身样式。

本次已完成账号内新建画布、草稿版本和 10 个组件的后端保存，并进行了浏览器预览。真实设备接入仍未完成。可用组件也可能受账号配置影响。

## 文件

- `巡桩问诊-组委会大屏配置.json`：主文件，引用本项目 GitHub 托管的 GLB，配置约数 KB；设备值使用等待占位。当前平台不宜保存大体积内嵌模型。
- `巡桩问诊-日间场景.glb`：独立静态模型，含停车场、充电桩、车辆、棚架、FishBot 和固定规划路线。节点包括 CP_01 至 CP_04、FishBot_01。
- `巡桩问诊-日间优化版.html`：辅助动态演示；不能当 GLB 上传，其巡检程序不会随模型导入。

## 编辑器操作

1. 新建测试大屏，先不要覆盖原作品。
2. 使用“导入/导出 → 导入 JSON”导入配置；此操作替换当前布局。
3. 等模型加载，确认不是默认机柜。如模型失败，使用模型字段上传本包 GLB。
4. 确认底图压暗 0、底图模糊 0、自动旋转关闭。按屏幕微调角度、缩放与位置。
5. 保存，退出并重新进入，验证模型和布局仍能加载。
6. 优先使用 JSON 中的模型 URL。当前平台的文件上传接口返回过无效资源地址；仅在上传后能实际读取 GLB 时才替换模型 URL。本地缓存不能作为跨电脑持久化依据。
7. 若 JSON 因账号组件限制不能导入，在组件库选机柜展示/3D 模型，手动上传 GLB，并配置原生信息卡。这条路径也需实际账号验证。

## 真实数据绑定

没有预填设备 ID、账号、MQTT 密码或杜撰接口。通过平台已有数据源与字段转换配置绑定：

| 组件 ID | 内容 | 所需真实数据 |
|---|---|---|
| patrol-task | 当前任务 | 编号、状态、当前点位、进度 |
| patrol-points | 巡检点位 | 点位编号和采集状态 |
| patrol-robot | 机器人 | 导航状态、电量、地图编号 |
| patrol-sensors | 采样 | 点位、温度、气体原始响应、采集时间 |
| patrol-alerts | 异常列表 | 后端生成的异常 |
| patrol-camera | 图像占位 | 后续替换为账号可用的图片/视频组件 |

信息卡结构为 `config.data = { title, icon, rows: [{ icon, label, value }] }`；异常列表为 `config.data = { alarmList: [...] }`。在平台数据编辑/转换面板中按真实接口组织字段。固定路线不是 Nav2 实时规划路线，MQ-135 未标定值不转换为 ppm。

## 完整运动联动的限制

原生组件只对整个模型应用变换，未发现更新 FishBot_01 内部节点的能力。若要求机器人按真实 ROS2 位姿在模型里移动，需组委会确认开放至少一项：模型节点位姿/动作绑定、可注册原生交互组件或受支持的网页嵌入。

在这些能力明确前，独立版动画只能作辅助演示，不能声称完整巡检逻辑已接入平台。

## 验收标准

- JSON 导入且模型外观正确；
- 保存、重新进入、跨浏览器验证资产持久化；
- 绑定一条真实温度，核对点位、读数与时间；
- 任务、异常和断线状态符合实际；
- 如要求模型运动，单独验证节点位姿能力。

完成对应验收后，才能将功能写成“已在组委会平台接入”。

## 实际接入发现的限制

- 原 1.36 MB 模型上传遇到 HTTP 413。现在导出复用相同几何并移除无纹理材质未使用的 UV，GLB 约 442 KB；没有增加 Draco 解码依赖。
- 平台上传接口曾返回成功，但返回的文件地址实际返回 HTML，无法作为模型资源使用。未修改组委会服务器配置。
- 约 600 KB 的内嵌布局能写入，但随后触发平台 MySQL `Out of sort memory`，使画布加载失败。原生配置现使用轻量模型 URL，不再默认内嵌 GLB。
- 模型文件来自用户已公开的 GitHub 项目。默认配置使用 main 分支文件；已配置的大屏可固定至具体提交，避免模型随其他修改漂移。平台查看模型需要浏览器能访问 raw.githubusercontent.com。
- 查看入口为“大屏搭建 → 巡桩问诊｜数字孪生接入版 → 编辑画布 → 预览”。不能把平台通用演示大屏中的默认统计当作本项目真实数据。
- 现场图像、机器人状态、任务和告警都保持等待占位，直到完成真实数据源绑定。
