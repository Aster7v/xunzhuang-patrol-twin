# 备用源码集成说明（不适用于仅能网页编辑的当前权限）

当前版本是独立前端演示工程，不包含 MQTT Broker、后端服务、数据库或经过测量的导航地图。

## 方式 A：嵌入完整页面

将完整工程放入现有网站的独立静态目录，例如 `/patrol-twin/`。目录名只是示例，不是已经部署的路径。

```html
<iframe src="/patrol-twin/index.html"
  title="巡桩问诊数字孪生"
  style="width:100%;height:calc(100vh - 80px);border:0"
  allow="fullscreen"></iframe>
```

同源宿主可在 iframe 加载后使用 `frame.contentWindow.patrolTwin` 调用模块 API。如果采用跨域嵌入，需要另行增加校验 origin 的 postMessage 适配层；当前版本没有通配接收跨域消息。

静态站点应设置 `.js` 为 JavaScript MIME 类型，确保 `vendor/`、`src/` 文件可用。Three.js 和 addons 已固定为 0.160.1。

## 方式 B：作为模块挂载

使用交付文件中的 `patrol-twin.js`（IIFE）和 `patrol-twin.css`。IIFE 内置自己的 Three.js，不依赖宿主全局 THREE。不要同时加载另一套本模块。

```html
<link rel="stylesheet" href="/patrol-twin/patrol-twin.css">
<div id="twin-container"></div>
<script src="/patrol-twin/patrol-twin.js"></script>
<script>
  const twin = window.PatrolTwin.mount('#twin-container', {
    config: {
      robotId: 'FISHBOT-01',
      mapId: 'demo-parking-v1',
      mapVerified: false,
    },
    onEvent(event) { console.info(event); }
  });
  // 离开页面时调用 twin.dispose()。
</script>
```

如使用 `id="patrol-twin"`，模块默认自动挂载。需要手动挂载时，请在加载脚本前设置 `window.PATROL_TWIN_NO_AUTO_MOUNT = true`，或像上例一样使用其他容器 ID。

CSS 限定在 `.pt-app` 之下。独立页的 body 重置只在 `html.pt-standalone` 中生效。默认容器高度为 100dvh，嵌入有顶部导航的平台时可在宿主覆盖容器高度；移动端允许纵向滚动。

Vue 页面中，在组件 mounted 时调用 `PatrolTwin.mount(element, options)`，在 beforeUnmount（Vue 3）或 beforeDestroy（Vue 2）中调用 `dispose()`。卸载会释放动画帧、WebSocket、Three.js 资源、事件监听和观察器。

## 实时数据与命令

演示与实时数据严格分开。切换实时模式：

```js
twin.setMode('live');
twin.ingest({
  type: 'pose',
  robotId: 'FISHBOT-01',
  mapId: 'demo-parking-v1',
  timestamp: new Date().toISOString(),
  payload: { frameId: 'map', x: 1.2, y: 2.3, yaw: 0.5 }
});
```

`ingest()` 会校验编号、字段、有限数值、时间及消息类型；调用方应捕获异常并记录。来自 WebSocket 的无效消息会被捕获，显示日志提示。相同流的旧时间戳和重复消息会被忽略。每个点位的 sensor 消息分别保序。

消息类型见 `消息格式.json`。示例时间戳是占位日期，发送前替换成实际采集时间，不能使用示例作为设备在线证据。

`sensor` 建议带 `taskId`，将采样与任务关联。`task` 新任务到来会清理旧任务的采样、图像与异常；采样最好在任务状态之后到达。温度阈值目前仅为演示配置，真实部署需依据设备和比赛要求调整；真正的异常事件由后端通过 `alert` 消息上报。

WebSocket 地址是后端输出标准 JSON 消息的应用接口，不是 MQTT 协议端口；模块不会实施原生 MQTT 协议。后端应处理 MQTT 订阅、认证、任务权限、重复命令、持久化和设备执行回执。不要把 Broker 管理密码放入前端配置。

真实命令通过挂载选项 `onCommand(command)` 提交：

```js
const twin = PatrolTwin.mount(element, {
  config: { mapId: '经过确认的地图编号', mapVerified: true },
  async onCommand(command) {
    const response = await fetch('/api/patrol/commands', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      credentials: 'same-origin',
      body: JSON.stringify(command)
    });
    if (!response.ok) throw new Error('后端未接受任务');
  }
});
```

`/api/patrol/commands` 是接入示例，当前工程不提供该接口。回调成功只代表提交完成，不能当作机器人已执行。页面依据真实 `task` 消息更新状态。默认未提供回调、地图未标定或数据过期时，真实任务按钮不可用。实时模式无模拟暂停和模拟复位。

## 坐标标定

ROS2 的 `map` 位姿需要由机器人侧或桥接程序通过 TF 获得，例如 `map -> base_link`。不要直接拿累计漂移的 odom 当 map 位姿。四元数需先转换为平面 yaw。

默认变换：Three X = ROS x；Three Z = -ROS y；Three yaw = ROS yaw + π/2，因为模型正前方为本地 +Z。

可配置 `transform = { scale, originX, originZ, rotation }`，其中 scale 为比例，rotation 是 ROS 平面坐标的旋转（弧度）。先旋转、再缩放与平移；Three Z 对 ROS Y 取反。

至少使用现场多个已知点校验比例、原点、方向和误差，再替换场地模型及 `points`。演示的点位 x/z 是三维世界坐标，不是可直接下发的导航目标；命令只发送点位 ID，后端必须将 ID 映射到经确认的 ROS 导航目标。
